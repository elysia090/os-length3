## Reverse requirements and the common construction law

INS/OUTS has byte/word/dword element width, DX port, 32/64 address size, DF,
optional repetition and decoded source segment. INS fixes ES/RDI; OUTS uses
the decoded RSI source (including FS/GS through existing C address authority).
A checked x86 law owns these roles and rejects malformed width/flags/encoding/
segment/port descriptor before backend use. No source opcode reaches the C VM.
REP/F2/F3 do not terminate on ZF here. A real common frontend defect marked
repetition only for memory-string operation rows, losing these port-machine
rows' REP flag. It is corrected at normalization, not guessed by the VM.

The exact per-instruction observation order begins with I/O permission EVEN
when repeated count is zero; zero count preserves full index/count parents.
After admission, the element is either:

```text
INS:  device read -> latch value -> memory store -> advance DI / repeated count
OUTS: memory read -> latch value -> device output -> advance SI / repeated count
```

32-bit address arithmetic narrows the effective address, but the original
parent is preserved on zero/fault. Successful element publication zero-extends
updated ESI/EDI/ECX. Non-REP does not use/change RCX. All flags remain unchanged
until the existing normal retirement/RF owner. Completed repeated elements
publish their pointer/count frontier before a later fault or wait. At 256
elements a QUANTUM barrier permits ordinary interrupt admission; no arbitrary
host clock tick is inserted.

The [Intel instruction reference](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf)
warns that an INS port read can precede a memory exception. The compiled model
uses that permitted ordering, retaining a successful read across a HOST
residency wait. A guest architectural fault releases the latch; an explicit
retry is not conflated with that host wait.

## The C decision and two-word residual

OUTS cannot read memory first then perform its first I/O permission check:
that reverses #GP-versus-memory-fault priority. Nor can the TSS bitmap simply
be checked again after a memory transaction: paging A/D effects can alias it.
The existing generic C I/O boundary now admits a checked transfer shape with
NO device effect, then uses that exact permission decision during its pinned
in-flight instruction. Its C owner binds generation, entry, private port,
coordinate and width/direction; it never holds a guest opcode or CPU image.
Only the active serialized compiled call can request CHECK/CHECKED. Fresh
entries reset it; stale/foreign tuple use refuses. Completed REP elements can
reuse the same decision, while an accepted interrupt/restart readmits a new
entry. Independent scalar IN/OUT still checks current rights.

The existing C checkpoint stores only cursor and the successful input/memory
word pending its second effect. INS residency resume cannot read the UART
again; OUTS console/clock resume cannot reread mutable source bytes. Memory,
device time, console tickets and MMU stay their existing C owners. No new
host callback, JS/Python instruction path, Linux syscall/VFS or opaque VM
INS/OUTS evaluator is introduced. Generated code is standard Wasm.

The fixed absent-COM2/3/4 bus ranges now accept 1/2/4-byte transactions wholly
inside their eight-port interval, returning the corresponding high word or
discarding output. Width is not decomposed into separate device accesses.
This is a stated absent-device contract corroborated by the reference system,
not a generic unknown-port fallback. DMA absent byte ports retain their narrow
contract; other targets/widths still require their own machine implementation.
