## Requirements derived from actual x86

The independent reference-x86 build VM executes genuine guest RSP through the
existing assembly capture trampoline and alternate signal stack, WITHOUT
calling a compiler or VM instruction helper. 672 prefix/allocation/raw-nesting
forms produce **8,064 CPU/RAM/fault records**. 3,984 fault; **2,784 retain stack
RAM changes**, but zero fault records change GPRs. All RAM outside the bounded
256-byte destination window is independently checked unchanged. Records save
that window plus CPU/fault fields, not repeated full RAM images.

The oracle is the independent native reference build VM, NOT a direct Windows
CPU claim or a product QEMU backend. No WSL kernel/source is used. It covers
zero/one/31 nesting, raw masked aliases (including the actual 214 -> 22),
0..65535 allocation, operand16/64 and ignored prefixes, aliases, earlier/later
readonly faults, chain reads, final permission probe, cross-page and invalid
addresses. The [Intel reference](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf)
also requires a write-permission check at the final stack position.

Let w=2/8 and n=raw_nesting & 31. Reverse the wanted final state:

```text
frame    = old_RSP - w
consumed = w * (n ? n+1 : 1) + allocation
new_RSP  = old_RSP - consumed
new_RBP  = operand64 ? frame : (old_RBP & ~65535) | (frame & 65535)
```

The common construction law expands, in order:

```text
write old BP word at old_RSP-w
for k=1..n-1: read word at old_RBP-k*w; write it at old_RSP-(k+1)*w
if n>0: write frame word at old_RSP-(n+1)*w
probe final new_RSP range for stack write permission (no payload store)
publish RSP/BP/RIP/retirement
```

Even operand16 frame-chain reads use FULL old RBP subtraction. Only stored
words and final BP narrow. The native low16-wrap test faults at `1233fffe`,
not an invented `1234fffe`. Operand16 retains OLD BP parent bits, not frame's
upper bits: an early backend mismatch at 420/4 exposed an unmasked full
frame value being ORed into that parent; masking before the existing partial
register publisher fixes it. Architectural faults keep original GPR/RIP/
retirement while retaining native-visible earlier RAM effects.

This one checked x86 law also feeds the existing common semantic construction.
The backend consumes ordered steps, not another private ENTER formula or a
runtime opcode. Its permission-only final probe uses existing C write_begin/
write_end with ZERO write_word calls, so it does not manufacture a read/store.
All SS/MMU/canonicality/page/residency checks remain the existing C owner.

## Why the residual is necessary and sufficient here

Restarting a non-architectural residency wait from the entry is not generally
safe: an earlier destination can overwrite a source already read, changing
subsequent replay. Architectural #PF restart is a DIFFERENT observation:
the CPU returns to the original registers with partial RAM, so a handler may
explicitly retry the whole instruction. A host page wait is not that fault.

The compiled transfer can rederive every address from unchanged architectural
RSP/BP and constant admitted source. Only two words need survive a resource
wait: the next action cursor and a successful read pending its store. A cursor
alone loses that pending read; a CPU snapshot or whole payload is unnecessary.
Nesting bounds the cursor to at most 63 actions, but the generic owner uses
two word-sized coordinates, not an ENTER-specific packed opcode.

The C execution latch owns the two-word frontier. A fresh selected call resets
it; an accepted resource wait retains it with original row/context/table/
generation. Completion, architectural fault, cancel/close and context revocation
release it. GET/SET/CLEAR are permitted only inside the bound serialized C call
and matching port generation. The checkpoint import carries NO opcode, nesting,
allocation, source decoder, host callback or CPU image. Standard entry ABI3 is
unchanged; only the private port extent is 64 bytes for this consumer.

Ordinary admission may be revoked by a payload write while the latched transfer
finishes. Successful resumed completion can therefore return STALE after exactly
one retirement; the next instruction requires readmission. That is explicitly
asserted, not treated as rollback/failure or ignored. A generic native C lifecycle
test checks complete/fault/cancel paths, stale-generation refusal and no refetch;
it and positive ENTER construction pass ASan/UBSan.

Exact Worker suspend/recovery must ALSO retain these two private C words with
the pre-existing continuation row/context. No such product snapshot/restart
acceptance is claimed. A Wasm/engine trap still requires the supervisor to
close/discard the affected machine; this checkpoint is not a proof of arbitrary
host-trap cleanup or permanently stopped Worker reclamation.
