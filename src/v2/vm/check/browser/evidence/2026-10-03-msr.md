# Common MSR boundary and actual Linux continuation — 2026-10-03

The shipped native bundle is unchanged. Its actual Linux `WRMSR` at
`0x14015f7` now retires through generated Wasm and the C VM. The ordinary,
non-isolated browser reaches **129,057,505 retirements / 64,417,792 admissions**
and stops explicitly at **LEAVE (`c9`), `0x1017cf3`, compile -102**.
Linux/PID 1/shell, production storage/network and cold shell three seconds
remain unachieved. A diagnostic pass is not Linux boot.

`machine.msr(port, operation, key, value)` is a serialized register boundary,
not a source decoder, address-special case or host MSR callback. The compiler
uses ECX[31:0] and EDX[31:0]:EAX[31:0]; RDMSR zeroes the EAX/EDX parents only
after success. RIP, RF clearing and retirement remain owned by the generated
instruction. Failed transfers preserve the entire CPU/hidden-cache state.
Reservations are aborted on success, fault, stale input and refusal.

The currently declared MSR subset is EFER, FS_BASE, GS_BASE and KERNEL_GS_BASE.
Other keys fault #GP(0), never a dictionary-default zero. This is not a complete
model-specific CPU/device register set. FS/GS base has one owner, the existing
hidden segment cache; EFER has its existing state field. Only inactive kernel
GS is retained in the bank, with absent row representing its known reset zero.
Duplicate/unknown owner rows or corrupt resumed bases are admission refusals.
SWAPGS exchanges active/inactive bases without changing selectors or descriptor
attributes. EFER accepts SCE/LME/LMA/NXE only; LMA writes are ignored and LME
cannot change while paging is active. Addresses are 48-bit canonical. CPL1–3,
reserved EFER bits and noncanonical writes produce pending #GP(0) without
retirement. Successful EFER writes revoke current execution admission.
See [Intel SDM Vol. 3A §2.2.1 and canonical-address rules](https://cdrdv2-public.intel.com/874249/253668-090-sdm-vol-3a.pdf).
