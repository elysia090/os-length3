## Derivation and responsibility boundary

The result is a bounded store extent, not a scratch FPU image or a VM opcode
callback. The compiler owns these pure equations over existing machine state:

```text
abridged_tag[i] = (physical_tag[i] != empty)
logical_ST(i) = physical_R[(TOP + i) & 7]
header = control | (status << 16) | (abridged_tag << 32) | (opcode << 48)
```

The common MMU first checks the complete 512-byte range, alignment and all
translations. A private synchronous frontier pins at most two physical
fragments. Generated code emits 52 eight-byte words in increasing offsets.
`write_begin`, `write_word` and `write_end` carry coordinates/scalars only;
they do not receive an FPU opcode, CPU snapshot, image pointer or JS buffer.
TOP uses a physical index, not a register-array rotation. CPU retirement is
published only after the stores. This is not a global work/span minimum claim.

The frontier remains 40 bytes: its cursor occupies former structure padding.
Sparse holes are untouched. It is consumed by end, invalid/stale calls,
abort/rebind/close or another memory access. Completed stores are not rolled
back. A host trap must abort/close before another admission. Directory/context
and residency are immutable during this synchronous single-owner operation;
this is not SMP/LOCK atomicity or a persistent shared-worker lease. Source
invalidation precedes each physical store, including a page-table alias.
Pinned destinations are not re-walked after such an alias store.

CR0.EM/TS raises #NM before CPU or output mutation. FXSAVE does not test a
pending x87 exception. FXSAVE and REX.W FXSAVE64 have different pointer
layouts; the latter preserves full 64-bit IP/DP. Software bytes 464..511 are
unchanged. These rules follow [Intel SDM, FXSAVE](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf).
The fixed CPU profile chooses a complete SIMD save even with OSFXSR=0,
MXCSR_MASK=0x0000ffff, zero selected reserved fields within 0..415, and
untouched 416..511. Implementation-dependent choices are not universal
physical-CPU claims. Full-range preflight and no partial payload store on
the tested protection fault match the independent reference QEMU TCG build
VM observation; that VM is an oracle only, never a product execution path.
