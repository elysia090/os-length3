## Red witnesses and exact CALL ordering

Previous browser startup stopped at `0x1e25239`, bytes `41 ff 14 24`,
`CALL [r12]`. The new general native CALL fixture first reproduced compiler
`-102`. Its `--observe` mode generated hardware observations independently
of compiler acceptance. A proposed "target check before stack store" also
failed the actual x86 observation: with a noncanonical target, the stack
word changed from `5a5a5a5a5a5a5a5a` to the return coordinate before #GP.

The shared lowering therefore implements this order, without changing CPU
storage until success:

```
T = target_operand(old_registers, old_RSP)   // read fault wins here
A = old_RSP - 8
store64(A, fallthrough)                     // full-fragment stack preflight
if not canonical(T): pending #GP(0)         // stack payload remains stored
publish RSP=A, RIP=T, retired+=1
```

Stack access faults prevent the target check. Target #GP leaves RSP, RIP,
all other CPU storage and retirement unchanged, but does **not** roll back
the successful payload store. A canonical destination is not prefetched by
CALL: a later destination-fetch #PF cannot unretire the CALL. The two ordered
read/write transactions are not mislabeled as one RMW operation. The memory
target's effective address and value are captured before decrementing RSP,
including `[rsp]`, `[rsp-8]` and `CALL rsp` aliases.

The C pending-fault boundary is not hardware exception entry. Native #PF
addresses are read from the actual signal frame; #GP/#SS pending metadata
names the target/stack operation address, not a claim that hardware CR2
changed. Exception-frame RF is excluded, not cleared from guest state.
CET, far indirect CALL and FS/GS bases are not admitted by this baseline.

Checks: **27 byte-identical native/C-Wasm modules, 6,912 complete x86/C-Wasm
CPU and stack cases**, including **2,150 actual exception frames** and
**448 target-#GP retained stores**. Forms cover all 16 GPRs, address sizes
32/64, SIB/extended GPR/RIP/SS addresses, split operands/stores and the actual
kernel `[r12]` encoding. Real protected/absent stack and operand pages test
fault competition, including simultaneous invalid target/stack. There are
162 TF/RF/AC/alias/wrap/stale refusals, plus separate next-fetch and physical
residency cases through the C MMU. No payload store occurs on failed
all-fragment stack admission.

## Register-bit lowering

After CALL, startup reached bytes `48 0f ba ee 3a`, `BTS rsi,58`, at
`0x1e2526b`. The general code-cut assertion was red (`-102`) before adding
BT/BTS/BTR/BTC. The common register lowering takes the index modulo operand
width, reads CF from the old bit before any destination write, preserves a
16-bit parent and zero-extends a modifying 32-bit result. BT never writes
the destination parent. ZF is unchanged; undefined OF/SF/AF/PF preserve the
selected representative and are excluded from hardware-defined comparisons.
CF definitions join the reverse flag frontier, including interior SETB
before a later flag kill. Memory-bit/LOCK register forms remain explicit
rejections rather than being treated as the pure register operation.

**60 ordinary post-linked ELF modules / 30,720 complete-state and defined-flag
cases** pass in direct Wasm and separately through the C table dispatcher.
All four operations, widths 16/32/64, register/immediate indexes 58/255,
self-aliases and composed ADD -> bit -> SETB -> XOR are covered.
The existing generic oracle's undefined-flags mask now includes this family;
it does not turn undefined flags into required host behavior.

Consulted primary architecture source: [Intel Volume 2A, CALL and
BT/BTC/BTR/BTS](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf).
The exact fault side effects above are additionally established by the
recorded hardware experiment, not guessed from simplified pseudocode.

and its indirect allocator call have progressed; decompression/boot are not
finished. The next exact unsupported instruction is **`SBB eax,eax` (`19 c0`)
at `0x1e24306`, compiler `-102`**. The extracted bundle's binary disassembly
independently confirms those bytes, followed by `OR eax,1`.

One table slot remains live. Delivery remains 47 exact HTTP 206 ranges,
