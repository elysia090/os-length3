## Architectural availability is not implementation completeness

The first post-LEAVE browser run incorrectly treated IA32_MISC_ENABLE as
unavailable, delivered #GP(0), then stopped on secondary IDT #GP(106).
That is an implementation classification bug, not an actual Linux fault.
The declared Intel CPU makes this register available. Likewise advertised
TSC/SYSCALL MSRs cannot legitimately be replaced by #GP or default zero.
Known but unimplemented keys now refuse execution admission with CPU/RIP
unchanged; CPL1–3 still faults before that refusal. Actual unavailable keys
remain #GP(0). These are explicit remaining boundaries, not a fallback.
