# Shared x86 construction and vector projection — 2026-10-06

## Required boundary

The Wasm backend consumes the instructions in the relinked accepted ordinary
x86 ELF. It shares exact instruction meaning with native compilation; it does
not re-optimize the original linked input, retain a private execution format,
or ask a VM instruction callback to implement a missing opcode.

The audit found that native already had instruction-to-SSA laws, substitution,
DCE/CSE, flags reduction and dependency waves, while the cold Wasm emitter
walked decoded instructions through separate handwritten rules. Older
`ARCHITECTURE.md` descriptions still named deleted Python/LKL routes.
The next real same-bundle gate was SHUFPS, not an absent decoder entry.

## One owner, no compatibility copies

Moved existing instruction semantics and six SSA operations into `x86/src`:
semantics, composition, compaction, normalization, sweep, region and ALU
reopening. Their public boundary is `x86/semantics.h`, `ssa.h`,
`ssa-build.h` and `ssa-opcodes.h`. Former postlink-private source/header copies

`postlink-compiler/src/internal/plan-codec.h`.

Native block formation uses that shared core. The cold compiler builds the
same x86 source population from one `sources.mk`; its unused SSA operations
remain eligible for linker elimination. This extraction is not a claim that
the scalar Wasm emitter already consumes the normalized block DAG.

The old `vm/wasm/vm.c`, its bench programs and trig source/check are deleted.
The modern machine is still `vm/wasm/entry.c` plus `vm/core`. Rebuilding it
produces exactly the old 70,499-byte module and SHA-256
`0c3142f523b4713e5034772569a73f32d6abe71f73c23d6da9bc45319c7e950f`.

The SDK helper's handwritten source/export/link lists (including a stale

output matches the normal Makefile build byte-for-byte.

## Derive the selection, then emit it

For a four-lane permutation with control c, output lane j selects
`(c >> (2*j)) & 3`. One-source operations select from one input region;
SHUFPS selects output lanes 0/1 from the old destination and lanes 2/3 from
the source. Word permutations apply that selection only to the low or high
eight-byte region and preserve the complementary input region.

Substituting equal register inputs removes the two-source distinction.
An output coordinate equal to its own input coordinate is identity, so an
entire identity publication disappears. The selector is a bounded coordinate
rule, not a sixteen-byte materialized intermediate or a per-opcode evaluator.

`pl_x86_vector_project` owns admission and the rule.
`pl_x86_vector_project_byte` evaluates one output coordinate.
Native instruction lowering validates the same rule. The Wasm emitter only
loads the required input(s), emits one static `i8x16.shuffle` when necessary,
and publishes one vector. The old `lower-vector-permutation.c` is deleted.

This covers PSHUFD, PSHUFHW, PSHUFLW, SHUFPS, MOVSHDUP and MOVSLDUP through one
rule. Memory inputs still undergo full sixteen-byte preflight after #UD/#NM
guards; identity does not erase a possible memory/alignment fault. Alias
inputs are captured before any publication. This is bit permutation, not
floating-point arithmetic or a global minimum certificate.
