## Explicit diagnostic profile and physical supply

Default `/src/v2/vm/check/browser/startup.html` retains the small 1,000,000
admission / 2,000,000 retirement diagnostic. `?budget=extended` explicitly
selects 50,000,000 admissions / 100,000,000 retirements, 8,192 physical slots
and at most 32 MiB ordinary VM memory. This changes diagnostic budgets, not
guest CPU semantics or the source distribution. The extended profile initially
allocates 1 MiB instead of 512 KiB to fit its bounded private directory.
Resource exhaustion reports `resident-quota`, never boot completion, invented
page contents or an assertion mistaken for an unsupported guest instruction.
Compile refusal also reports at most 15 raw source bytes and CPU coordinates;
the diagnostic host does not decode them.

Actual resident pages grow to 2,788 / 12,058,624 VM bytes as demanded output
extends beyond the original image. Directory reservation is 393,200 bytes;
it is not an object-sized disk/root reconstruction. Fetch remains exactly
47 HTTP 206 ranges / 3,056,640 bytes with a 65,536-byte chunk cache. 2,775 page
supplies include virgin zero/RAM pages; source acquisition remains 3,022,848
bytes. Physical appends and memory.grow preserve the C owner and directory,
not VM reopen/rebuild. This is still local diagnostic SHA-256, not production
signed-root/AEAD/ECC authentication or dirty eviction/recovery.
