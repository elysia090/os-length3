## One pure permutation

The existing shared x86 decoder and native post-link semantics already own
BSWAP. Only common cold Wasm pure-register lowering was missing; no kernel
function, opcode skip, guest import or VM decoder was added. Accepted sizes
are 32/64 bits; the 32-bit destination defines a zero upper parent half.
All flags remain unchanged; LOCK and undefined 16-bit forms refuse without
publishing. This follows the manufacturer's
[Intel SDM Volume 2A, BSWAP](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf).

```text
S(x,m,k) = ((x & m) << k) | ((x >> k) & m)
reverse32(x) = rotl32(S(x,0x00ff00ff,8),16)
reverse64(x) = rotl64(S(S(x,0x00ff00ff00ff00ff,8),0x0000ffff0000ffff,16),32)
```

Permute adjacent bytes, then halfwords, then rotate halves. Read the current
SSA-local slice value rather than entry RAM; reuse the existing register
publication path. No source payload, extra scratch memory or flag definition
is required. This establishes the permutation, **not** a global work/span
minimum or an engine-machine-code speedup.


There is no IN/OUT/RDTSC in this loop. The current C PIT/PIC advances only on
accepted clock requests from such instructions, so the pure loop cannot cause
the next IRQ merely by executing more source instructions. Later clock events
are absent while the loop runs. This is a missing asynchronous machine-clock
boundary, not evidence that a compiler must fuse/skip the Linux wait or invent
a jiffies update. Next add an independent supervisor clock sample at a safe
