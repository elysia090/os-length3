## Closed word snapshots

The common x86 law now validates FNSTCW m16, FNSTSW m16 and FNSTSW AX as the
same no-wait current-word transfer. Decoded argument, operand width/class,
memory direction, cut/trap declarations and prefix/fault context must agree.
Both native semantic formation and the cold backend consume that law.
The backend emits ordinary loads/parent masking and the existing typed C
memory access; no new VM import, opcode callback or host FPU operation exists.

Intel's [FNSTCW/FNSTSW definitions](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf)
distinguish these no-wait operations from FWAIT + a subsequent store. They
do not consume pending unmasked floating exceptions. CR0.EM/TS causes #NM
before destination access. A memory form writes exactly two bytes; AX keeps
the other 48 parent bits. RIP/RF/retirement use the existing instruction owner.
Condition-code side effects specified as undefined are concretized as retained
bits in this projection, not claimed as independently defined by the manual.

24 prefix/destination forms produce 768 actual native x86 observations,
including randomized control/status, empty/occupied tags, TOP and payloads.
Native and cold C bytes match at all 24 forms. Direct emitted execution and
C MMU/table execution each match all 768 complete CPU/FPU records. Another
496 modeled faults cover EM/TS priority, nonpresent/readonly memory, atomic
cross-page writes and pending exceptions without changing CPU/RAM on failure.
The shared/native law rejects 288 malformed descriptors; three decoder-proved
LOCK forms retain architectural #UD rather than an unsupported-opcode fallback.
These native instructions run on the build QEMU CPU, not physical silicon.

The FXSAVE logical-ST to physical-payload/tag observation conversion is now
one test helper, shared with the old FXSAVE/FNINIT tests and the compare oracle.
The separate older conversion copies are removed. Provider dependencies are
declared before their Make rules, so early check binaries cannot silently omit
library timestamp dependencies. Full current compiler/postlink checks and
scoped ASan/UBSan pass without warnings. Historical `parity`/`direct-check`
target names no longer exist in this product; current `check` includes native,
direct control and completeness checks. No old targets were revived.

Re-inventorying ACTUAL make recovers **31** final coordinates:
7,183 -> **7,152** missing, x87 3,343 -> 3,312. Its first miss is STILL
`dfe8` at `0xa0c9`. This is finite common-grammar progress, not Linux boot,
full coverage, a new root, minimum work/span or a distribution speed/size claim.
The previous authenticated-image regression still passes 1,152 comparisons
with six constructions and zero execution compiler calls.

## A large exact compare gate, still red

`x87-compare-observe` independently executes the four register FCOMI/FUCOMI
and pop variants, all eight source indices, masked and unmasked invalid/
denormal controls, and the full 16 x 16 operand matrix. The values include
signed zeros, one-ulp extended-precision differences, normal/denormal/pseudo-
denormal, both infinities, QNaN/SNaN, unsupported representation and empty tags.
It retains one bounded observation buffer and streams each form to test files;
these files are not release payloads or an executable fallback.

16,384 observations / 64 forms yield 4,966 unmasked exception states and
2,483 suppressed pops. The semantic distinction matters: the current compare
can latch an exception while the following waiting instruction delivers #MF.
Intel's [x87 exception model, section 8.7](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf)
also distinguishes CR0.NE native #MF from legacy FERR/IGNNE/external interrupt
handling. Neither an immediate fake #MF nor unconditional pop is adequate.

The build CPU reports GenuineIntel, but remains QEMU. It keeps C1 in 14,520
rows, unlike the instruction table's simple “C1 set to zero” description.
This discrepancy is recorded, not silently fitted as a hardware proof.
The final CPU contract and stronger independent observation must resolve it.

`check-x87-compare.mjs` is a non-skipping gate over that complete matrix. It
starts with the ACTUAL make blocker, FUCOMIP ST(0),ST(0), then visits all other
forms. It is genuinely **red at `dfe8`, compiler -102**. There is no approximate
backend or success result for this gate. Required next work is a shared exact
80-bit relation/exception law, deferred exception and pop/flag publication,
pending #NM/#MF/legacy event priority, then direct C-Wasm/native parity and
full actual-image re-inventory before any Linux root publication.
