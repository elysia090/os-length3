## Architectural boundary

The frozen `machine_state` ABI 1 stays 1,256 bytes. A separately versioned
136-byte `machine_segments` cut contains eight hidden base/limit/attribute
caches and MOV SS inhibition. Selectors remain in the original state; FS/GS
bases have one owner in the cache, not another MSR-list copy. Exact suspend
must retain both cuts. This is an explicit extension, not a claim that the old
ELF proof certified a complete machine with these previously absent fields.
Complete execution/context attestation and suspend plumbing are still open.

Register-source MOV loads for ES/SS/DS/FS/GS use generated Wasm importing the
typed **C** `machine.segment` boundary. It receives a resolved selector and
segment rank, not instruction bytes/opcodes or a source register number.
GDT/LDT bounds, descriptor type/privilege/presence, supervisor paging and the
descriptor Accessed update precede selector/cache publication. Failed accesses
can leave architectural paging A/D updates, but do not retire or publish the
new selector/cache. Any RAM mutation still revokes execution admission.

MOV SS sets an explicit shadow. While it is active, only a single-instruction
next cut is admitted. Successful retirement consumes the old shadow; another
MOV SS does not extend it. Pending faults/misses retain the shadow until actual
continuation or exception delivery. Interrupt/debug/exception **delivery** is
not implemented by this state bit.

The MOV/load checks follow the
[Intel instruction reference](https://cdrdv2-public.intel.com/868141/253667-089-sdm-vol-2b.pdf)
and the data-segment privilege rule in the
[Intel system-programming reference](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366821.pdf).
The baseline explicitly chooses null data selectors to clear the cached base.
This is not portable Intel/AMD behavior: Linux's own
[null-segment detection](https://github.com/torvalds/linux/blob/master/arch/x86/kernel/cpu/common.c)
tests that difference empirically. The frozen v1 release CPU metadata has not
been replaced or recertified; future projection publication must fix the entire
behavior/CPUID contract, not only attach a marketing CPU name.
