## Derivation and single ownership

The required integer coercion is exact, including INT64_MIN, and independent
of x87 precision/rounding control: the 64-bit explicit significand represents
every signed64 integer without rounding. Work with unsigned words throughout:

```text
x     = sign_extend(input, width)
s     = x >> 63
m     = (x XOR (0-s)) + s
l     = 63 - BSR(m, zero_representative=-1)
sig   = m << l                      [lane shift modulo 64; zero stays zero]
exp   = m == 0 ? 0 : 16383+63-l
se    = (s << 15) | exp
tag   = m == 0 ? zero : valid
```

The zero BSR representative yields l=64, not a C shift-by-width. The common
lane semantics define the shift; unsigned magnitude also avoids signed
INT_MIN negation. The plan has one x86 owner in `x87-value.c`, alongside the
existing relation plan. No parallel old compare file remains. `pl_builder`
and projected compaction perform DCE/CSE and dependency scheduling. The
measured maximum **14 live SSA nodes / span 11** is an abstract graph metric,
NOT the emitted x86 instruction count, a global minimum or speed claim.

The same validated pure-plan emitter accepts bit-summary's value projection
only, with the exact BSR64/zero representative descriptor. It cannot silently
emit a raw flags view. The SSA is transient construction evidence; product
execution is ordinary Wasm, not an SSA/opcode interpreter. Integer coercion

## FILD publication

One checked descriptor law owns signed16/32/64 load width and FOP derived
from decoded opcode/ModRM, including legacy prefixes. #NM precedes a previous
unmasked #MF/legacy FERR wait; these precede C-MMU operand access. The complete
readonly/cross-page load must succeed before FPU state is modified.

Normal load clears C1, writes only the new physical TOP payload/tag and pushes
TOP modulo eight. Masked stack overflow sets IE/SF/C1 and pushes the indefinite.
Unmasked overflow latches IE/SF/C1/ES/B and FOP/FDP without changing TOP,
payloads or tags. FIP names the admitted instruction. No physical register
array rotation, floating conversion to f64, VM arithmetic callback, or linked
SoftFloat implementation is used. Existing C memory and deferred event
boundaries retain their ownership. VM and published native bytes are unchanged.
