## Bounded physical device state

The common C transfer owner performs long-mode context and CPL/IOPL/TSS
permission checks before device selection. COM1 supports one-byte register
accesses, divisor banking, FIFO reset/threshold/overrun, scratch, loopback,
THRE rearming and clear-on-read observations. Other ports, wider transfers,
break-line transport and external transmission remain explicit refusals.
Generated Wasm still owns successful RIP/RF/retirement; C owns the device.

`vm_uart` is 40 bytes: a bounded 16-byte receive ring, register effects and
one timeout deadline. LSR, interrupt identity and IRQ4 are projections of that
state, not duplicate materialized registers. There is no allocator, TX queue,
guest source decoder or timer history. Half-bit integer units represent
5-bit/1.5-stop framing; the four-character timeout rounds upward. Overflow
uses an unreachable deadline rather than creating a wrapped early event.
Monotonic time comes from the existing C clock owner.

Non-loopback THR returns an external-operation requirement **before mutation**.
The product does not call `transmit_commit` until a sink is actually owned.
The independent null-sink trace test explicitly accepts the oracle sink;
it does not authorize the product to silently discard console bytes.

The virtual register profile follows the [pinned QEMU 11.1.0 serial model](https://github.com/qemu/qemu/blob/v11.1.0/hw/char/serial.c)
and the manufacturer-authored [PC16550D data sheet](https://media.digikey.com/pdf/Data%20Sheets/Texas%20Instruments%20PDFs/PC16550D.pdf).
Fixed modem inputs outside loopback do not claim physical modem polling,
delta interrupts, external receive errors, DMA transport or silicon baud
fidelity. Independent frozen-clock register comparisons do not validate the
deadline's wall-clock accuracy.

## Red and verification

* The old VM returns ENTRY_MAP on generated port-`0x3f9` input. The new common
  path closes that red without a Linux-specific bypass.
* Native C device checks: 1,561 register/FIFO/IRQ observations, malformed
  transfer immutability, explicit external-TX refusal and deadline overflow.
* Independent QEMU TCG qtest: 4,426 operations / 2,521 read observations,
  including divisor/scratch/register masks, IIR rearming, all loopback modem
  outputs, FIFO switching, reset, overflow and ordering. No Linux boot claim.
* Actual cold-compiled C-Wasm transfers: six IN/OUT forms and 6,186 complete
  CPU/segment comparisons, including 336 precise #GP and 3,810 unsupported
  width/external-TX/break refusals. Permission precedes device-width selection;
  failed transfers retire nothing and leave CPU/device state unchanged.
* Native I/O permission tests now cover 7,680 cases. UART loopback/FIFO output
  and IRQ are checked through generated Wasm and the C VM, not a JS UART model.
* Full product checks and all C VM core ASan/UBSan pass. Previous RTC, PIC,
  IF/shadow/IRQ entry, I/O, exchange, source-admission, initial boot-plan and
  independent fault-entry/IRET regressions remain green. These bounded tests
  are not an ISA/MMU/device completeness proof.

Reproduce register and generated-provider checks separately:

```sh
node data/oracle/check-uart-qtest.mjs QEMU EXECUTOR [EXECUTOR-ARGS...] UART-CHECK
node data/oracle/check-uart-provider.mjs VM.WASM COMPILER.WASM

```

The qtest driver starts a paused, network-disabled reference machine with
an explicitly accepted null serial sink; it is never a product executor.
