## Single semantic path

The old C VM is red under the new actual-provider test: `C device boundary must
exist` (`vm_io` is absent). The previous browser refusal was scalar IN AL,61.
The ordinary decoder now admits all immediate/DX scalar IN/OUT widths 8/16/32
and RDTSC through general generated C boundary calls. No runtime opcode
interpreter, guest patch, calibration constant or kernel-coordinate handler
was introduced. Arithmetic, register binding and retirement remain compiled
SSA; device state, permissions and pending events live in C.

The [Intel instruction manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)
define the privilege boundary. CPL <= IOPL needs no bitmap. Otherwise a cached
64-bit TSS supplies its I/O map; every scalar I/O checks the required two-byte
bitmap word through the supervisor C-MMU. Missing permission bits produce
#GP(0); residency and page faults remain precise. CR4.TSD protects RDTSC at
nonzero CPL. An unadmitted TSS cache is refused, not guessed.

The compact clock owner binds a unique ticket to generation, private port,
RIP and operation. Waiting or repeating a wait cannot mutate CPU/device state
or retire. Only a matching, nondecreasing reply makes it executable. The
device transition consumes that reply once. Exact duplicate consumed replies
are harmless; stale generation, wrong identity and backward time are refused.
Cancellation/close preserve the ticket high-water; wrap refuses rather than
reuse a ticket. A new Worker needs a fresh externally owned generation.

The diagnostic supervisor samples **active C execution nanoseconds**, excluding
asynchronous compilation/delivery/UI stalls. A fixed 1 GHz virtual TSC returns
that time; it is not calculated from retired instruction count. This is an
explicit diagnostic clock contract, not a production RTC/interrupt/recovery
contract. TSC MSR access still refuses and must eventually share this owner.

The [Intel 8254 specification](https://www.scs.stanford.edu/23wi-cs212/pintos/specs/8254.pdf)
gives the PIT model. Only binary mode 0 is currently supported, with three
channels, command/count latches and channel-2 gate/speaker/output bits. The
1,193,182 Hz counter uses closed-form time differences, no per-tick loop.
Loading takes the next pulse without decrement; gate pauses counting; the
first byte of a word reload stops counting until the second. Zero means 65,536.
First count/status latch wins, and status reads precede count reads. Other
modes, BCD, wider PIT I/O and undeclared devices explicitly refuse. There is
no IRQ routing, fabricated refresh bit, parity signal or speaker audio.
QEMU's documented/source approximations are not claimed as an exact PIT oracle;
these model tests follow the cited device specification.
