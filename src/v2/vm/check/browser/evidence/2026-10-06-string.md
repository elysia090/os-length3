## One decoded law, one element lowering

`x86/semantics.h` now owns the string kind, element/address width, repetition,
comparison termination, implicit memory roles and source segment. Both native
SSA construction and the independent Wasm backend consume this decoded law.
The old separate Wasm admission/implicit-source walk is replaced, not retained
as a fallback. Repeated native machine transfers retain their existing native
selection; this is not a claim that every scalar Wasm body uses normalized SSA.

The existing element emitter now handles MOVS, STOS, LODS, CMPS and SCAS,
including REP/REPE/REPNE. Generated ordinary Wasm calls the existing C memory
access boundary. No guest opcode decoder, JavaScript/Python instruction
execution callback, Linux-specific function rule or new execution format is
introduced.

Source reads precede destination access. A failing or missing access commits
neither a partial element nor its pointer/accumulator update. Comparisons use
the new ZF to choose REPE/REPNE termination. Zero count does not define new
comparison flags or load a new accumulator. DF chooses the signed stride.
Each call completes at most 256 elements; a remaining count returns QUANTUM
without advancing RIP, clearing RF or retiring the source instruction.

## Red observations and sparse residual state

The former backend rejects a non-REP LODS at form 16 with `-102`. A separate
native-only capture establishes the new forms before using their emissions.

Native REP captures also exposed an incorrect eager narrowing of the RSI/RDI
parents in LODS/CMPS/SCAS: zero count and first fault preserve their original
upper halves. Successful elements define the new narrow parents. ECX is
narrowed at entry. Existing independent MOVS/STOS observations differ: their
used index parents are narrowed on entry, even for zero count/first fault.
That existing behavior is preserved and rechecked against fresh captures;
the LODS/compare fix is not blindly applied to the older families.

REPE/REPNE comparison faults restore the flags from the beginning of the
instruction, including a fault after a previous quantum. The existing C
instruction owner retains only the six arithmetic bits in a `uint16_t`, not a
CPU/RAM snapshot. Completed comparison flags remain visible at a quantum;
fault rollback restores those six bits while retaining the completed GPR/RAM
frontier. [Intel's instruction manual](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2b-manual.pdf)
describes the REP counter, comparison termination, restart and fault-flag
contract (REP/REPE/REPZ/REPNE/REPNZ entry).

Old C execution-owner tests fail on all 64 initial arithmetic-bit combinations
when a quantum precedes a fault. The corrected owner passes. Context change,
close/reopen and accepted interrupt cancel the residual latch. Cancellation
does not erase completed-prefix accounting.

An old VM rejects `vm_clock_poll` at a completed REP quantum: actual ENTRY_MAP
6, expected CLOCK barrier 18. A quantum is now interruptible, unlike pinned
resource/I/O/descriptor/console transactions. Time does not execute an element.
A real C-PIT/PIC IRQ saves the current frontier, discards the old slot latch,
and requires fresh admission after IRET. This is checked both for explicit
test rows and the actual C source-owned dispatcher. No host IRQ injection or
relaxation of stale/duplicate clock tickets is used.
