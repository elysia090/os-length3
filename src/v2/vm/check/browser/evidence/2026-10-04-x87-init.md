## An initialization, not a no-op or a new FP interpreter

The common decoder already classifies FNINIT as a precise x87 cut. Its
argument now has a shared symbolic name, without a format or ABI change.
Common C Wasm lowering emits the following transformation on existing
machine-state fields, with no new VM import or floating-point callback:

```text
if CR0 & (EM | TS): precise #NM before any CPU mutation
(control, status, tag, opcode) := (0x037f, 0, 0xffff, 0)
IP := 0
DP := 0
```

Adjacent control words use one 64-bit store; IP and DP use two more. No
scratch FPU state, payload copy or data-register zeroing is introduced.
Physical x87 payload, XMM, MXCSR and integer flags remain unchanged. Normal
retirement advances RIP/count and clears RF; #NM preserves all CPU state
including RF. No global work/span optimum or JIT speedup is asserted.

The no-wait instruction does not check pending unmasked x87 exceptions.
FWAIT followed by FNINIT is a different two-instruction sequence and is
not silently admitted as this cut. These rules follow the manufacturer's
[Intel SDM Volume 2A, FINIT/FNINIT](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf).
LOCK refuses; other tested ignored prefixes preserve instruction semantics.
