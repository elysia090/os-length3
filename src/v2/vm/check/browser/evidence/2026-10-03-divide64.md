## Red and exact normal form

The previous browser refused `48 f7 ff` (IDIV RDI) at
`0xffffffff81413f53`. The shared register-division lowering excluded width 64.
The new general native observer first captured all 32 register forms without
lowering, then reproduced `divide form 24 red: compiler=-102`. No guest
coordinate, kernel function or precomputed quotient was introduced to fix it.

The [Intel DIV/IDIV definitions](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf)
require the full RDX:RAX dividend, quotient/remainder and precise #DE for zero
divisor or an unrepresentable quotient. Signed division truncates toward zero;
the remainder follows the numerator's sign. Undefined arithmetic flags use
the existing incoming representative. Faults retain registers, RIP, retirement
and RF; the common epilogue clears RF only on success.

Let `B=2^64`, `N=H*B+L` and nonzero unsigned divisor `D`. The necessary and
sufficient unsigned range condition is `H<D`: if `H>=D`, `N>=D*B`; if `H<D`,
`N<D*B`. This guard precedes division. The quotient fits u64 exactly in the
second case. If `H=0`, ordinary i64 unsigned division/remainder suffice.

Otherwise one compiled restoring loop consumes exactly 64 low-word bits:

```text
precondition: 0 <= H < D
repeat 64 times:
    t = 2*H + top_bit(L)             # conceptual 65-bit value
    bit = top_bit(H) OR (low64(t) >= D)
    H = low64(t) - bit*D
    L = (L << 1) OR bit
result: L = quotient, H = remainder
```

Since `t<2D`, one subtraction is sufficient and reestablishes `0<=H<D`.
The 65th-bit test matters for divisors above `2^63`; discarding it would be
incorrect. All actual operations are modular i64. The loop has fixed 64
iterations, no ISA interpreter, host integer helper, C signed overflow,
floating point or Wasm trap.

For signed division, first retain numerator/quotient sign bits. Normalize
the divisor by modular absolute value and the complete negative dividend by
`(H,L) -> (~H + [-L==0], -L)`. This works even for the minimum signed 128-bit
numerator. Apply the unsigned rule, then require quotient magnitude at most
`2^63-1+negative_quotient`. Restore quotient and remainder signs before any
architectural publication. Positive `2^63`, zero divisor and all larger
quotients become #DE, including signed MIN/-1; no `i64.div_s` overflow escapes.

The emitted body uses six existing i64 temporaries and the existing precise
fault port; it imports only shared memory. Divisor and both dividend halves
are captured before aliased RAX/RDX publication. The same path covers unsigned
and signed 8/16/32/64 register operands. Memory-source division still refuses.
This exact bounded implementation is not a proof of minimum work/span for
general 128/64 division; faster wide algorithms remain a separate optimization.
