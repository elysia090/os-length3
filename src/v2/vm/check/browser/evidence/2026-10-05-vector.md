# Precise SIMD transfer frontier — 2026-10-05

## Common lowering, not a VM opcode callback

The preceding independent startup stopped at `movdqu (%rdi),%xmm0`.
Before adding lowering, the independent native fixture saved 4,096 complete
CPU/RAM observations (32 forms, 128 inputs each); compilation of form zero
was red with grammar -102. The unchanged observations now pass through the
common C compiler and actual C-Wasm MMU in direct and C-dispatched execution.

Legacy MOVDQU/MOVDQA/MOVUPS/MOVAPS/MOVUPD/MOVAPD transfers and MOVNTPS/MOVNTPD
stores share one lowering. Six ordinary families cover memory load/store and
register transfer, with high XMM registers. Twelve additional address forms
cover address-size truncation, stack, indexed, RIP-relative and displacement
coordinates. MMX, VEX, LOCK and FS/GS forms remain explicitly unsupported.
MOVD/MOVQ scalar transfers and vector arithmetic are not covered by this gate.

The Intel [SDM](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)
revision 093, Vol. 2B MOVDQA/MOVDQU descriptions and Vol. 2A exception classes
1/4 are the source for transfer width, alignment and SSE control priority.
The fixed SSE/SSE2 profile checks CR0.EM/CR4.OSFXSR (#UD), then CR0.TS (#NM),
before operand access or CPU publication. Aligned forms require 16-byte
alignment; MOVDQU remains unaligned. No host FP arithmetic is involved.
Register transfers preserve the captured pair under aliasing; MXCSR, x87,
flags (apart from normal RF retirement) and unrelated XMM/GPRs are unchanged.

For memory, all sixteen bytes are preflighted before either XMM publication
or the first store. Two independent scalar reads/stores would incorrectly
publish a partial operand on a second-page fault. Reads use the generic C
`read_pair` boundary; writes use the existing bounded write frontier. Neither
boundary knows a mnemonic. Wait/fault retains the complete old CPU and payload.

## Physical read without a 16-byte output image

After the same preflight, at most two pinned fragments suffice. Let n be the
first fragment length, L(p,k) the little-endian k-byte load (L(p,0)=0), and
p/q the two fragment bases. Substitution gives the two output words directly:

```text
n >= 8:
  low  = L(p,8)
  high = L(p+8,n-8) | L(q,16-n) << (8*(n-8))  [second term only if n<16]
n < 8:
  low  = L(p,n) | L(q,8-n) << (8*n)
  high = L(q+8-n,8)
```

This removes the intermediate 16-byte record and rereading it, without a
second translation, payload copy or RMW reservation. No shift reaches 64.
All sixteen crossing geometries and fault/wait/stale cases are checked against
independent byte-derived words. The private pair port has a 56-byte ABI;
both words remain unchanged on preflight failure. Dispatcher code fetch may
independently use its ordinary scalar port value, so that value is not mistaken
for an architectural register preservation requirement.
