## Meaning and one implementation

The native decoder already produces the typed READ_SELECTOR descriptor.
Preserve it, including its exact source/destination binding and precise cut.
Do not relabel selector reads as ordinary GPR copies or descriptor loads.
For rank `s` in ES/CS/SS/DS/FS/GS, the value is simply:

```text
v = machine_state.system[MACHINE_SYSTEM_ES + s] & 65535
register16 = (old_parent & ~65535) | v
register32 = v
register64 = v
memory     = store16(v)
```

The existing common operand read emits one architectural word load and a
16-bit projection. The existing parent write and C-MMU store publish it.
Register reads occupy one typed system cut with no function import, port,
descriptor lookup, source scan, host selector or duplicate segment dictionary.
Memory destinations use the same common operand read and precise C access.
Even with REX.W, memory stores only two bytes. Flags, visible/hidden segment
state and unrelated parents are unchanged; ordinary successful retirement
clears RF. Failed memory access publishes no CPU/retirement/payload change.

The [Intel MOV specification](https://cdrdv2-public.intel.com/835752/253667-sdm-vol-2b.pdf)
defines the zero-extended Intel 64 register result, two-byte memory operand,
and unchanged flags. No guest descriptor is consulted by a visible read.
Descriptor writes and their fault/shadow semantics remain separate.
