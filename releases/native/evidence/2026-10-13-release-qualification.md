## Candidate defect and source repair

In the ordinary e67 console, `command -v ip` chooses BusyBox's built-in applet despite `/usr/bin` leading PATH. `ip route replace default ...` produced a real general-protection fault in BusyBox. The installed `/usr/bin/ip` is the declared iproute2 provider and performed the same operation successfully. `ip -Version` through the applet also failed to return and was interrupted through the guest terminal.

An ash ENV alias selecting `ip=/usr/bin/ip` was initially tested on the actual e67 guest. That limited interactive repair is superseded: the fixed BusyBox 1.36.1 source documents that `FEATURE_SH_STANDALONE` bypasses PATH and `FEATURE_PREFER_APPLETS` also affects `xargs`/exec. Both flags and the dependent nofork flag are disabled in the fragment and resolved lock. Early init's remaining bare `cat` is made explicit as `/bin/busybox cat`. This covers ordinary noninteractive shells and applet exec as well as the console. It does **not** alter immutable e67; a fresh signed successor must pass `standard-provider-check.sh`.

The applet fault also reproduces on native x86-64. On the same e67 kernel, the retained ordinary BusyBox exits 0 for the loopback route operation, while the candidate's optimized BusyBox exits 139. [The runtime counterexample](2026-10-13-busybox-runtime-counterexample.json) keeps exact binary/log digests and the first invalid multicall-basename test separately. A green oracle boot summary is not a passed equivalence result. Structural proof receipts and producer binding remain their named observations, while formal gate 5 is now failed.

Static inspection identifies a bounded relative table whose target is already formed in RAX before LEA reuses its former RDX base as an argument. `shared_base_consumer` incorrectly rejected that later base write. The source correction allows base reuse only after ADD has captured it; writes to the actual target still reject the table. The native regression exercises all thirteen cases and the overwritten-target negative before any successor signing. A subsequent same-kernel test reports ordinary/old/fixed exits **0/139/0**. The fixed smoke ELF SHA-256 is `ae5250691672e14ccfc6912234bae01415c47cd649ff88e3beea2d248db3d9cd`; it is not labeled as the fresh final producer-cut artifact. Source cut `2a96a04e464be6bbaffe4b17e0d6a32e84a63a7a4054ca8b969b467268fffbf8` is an explicit derivative of the prior fixed archive, with nine byte-pinned file changes; it is not claimed to be an unchanged historical Git commit. Fresh complete candidate verification remains pending.

The repaired project's verifier still accepts the actual old bad ELF with exit 0. Its separate reader checks proof/ELF structure, build identity, source SHA-256 and reported cost constraints; it does not independently establish all runtime semantics. Neither its green message nor a producer's self-reported flags are semantic equivalence evidence. The named runtime counterexample remains a failed case, and a semantic-witness checker remains required. An ad hoc bad-hash list would not resolve that missing boundary.
