# Common MXCSR transfer — 2026-10-04

## Red, contract and lowering

The preceding real browser Worker terminated normally at the shipped Linux
instruction `0xffffffff81034e31`, bytes `0f ae 54 24 0c`:

```asm
ldmxcsr 12(%rsp)
```

It had retired 174,000,486 instructions, initialized timers/futex/NETLINK and
checked every decompressed byte, but had not reached PID 1 or shell. See the
unaltered preceding receipt.

The decoder already represented both legacy MXCSR transfers. Common Wasm
admission rejected the independent native fixture with `-102` before lowering.
The new `lower-mxcsr.c` accepts the descriptor, not Linux addresses or source
mnemonics in an execution callback. Both raw executable pages and accepted
optimized ELF use the same cut planner and emitter.

For the fixed SSE/DAZ-capable profile, the admitted operation is derived as:

1. CR0.EM or CR4.OSFXSR=0: precise `#UD(0)` before the operand.
2. Otherwise CR0.TS: precise `#NM(0)` before the operand.
3. Derive the effective address once and complete the exact four-byte C MMU
   transfer. Its canonical/SS checks, permissions, page fault or residency wait
   must succeed before any CPU publication. A read-only mapping is valid for
   LDMXCSR; STMXCSR requires write permission on all fragments.
4. LDMXCSR tests `value & 0xffff0000` after that complete read. A nonzero result
   yields `#GP(0)`, with old MXCSR/CPU/retirement intact. Otherwise a narrow
   32-bit store publishes MXCSR alone. Adjacent MSR count/key fields survive.
   STMXCSR writes the existing 32-bit MXCSR directly, without an output image.
5. The common successful-retirement epilogue advances RIP/retired and clears RF.
   A fault/wait returns before that epilogue; a resumed wait reuses the same
   admitted operand, not a patched guest page table.

Installing exception status bits with the corresponding mask clear does not
itself raise a SIMD arithmetic exception. No host floating-point instruction
or host MXCSR is used by the generated guest function. Its only imports are
`machine.memory` and the existing C `machine.access` boundary. There is no new
VM export, opcode handler, interpreter or execution fallback.

These rules follow Intel SDM Volume 2A, LDMXCSR and Table 2-22 (Type 5
exceptions): [official manual](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2a-manual.pdf).
The original numeric descriptor is unchanged; naming operation 28 does not
change optimized-x86 serialization or introduce a new format.

## Independent observations and limits

Before implementing lowering, `mxcsr-check --observe` captured 4,096 actual
x86 observations, including 1,680 fault frames, in the independent reference
build VM. After lowering, every complete observation record remained
byte-identical. Sixteen forms cover load/store, ordinary and extended bases,
32-bit address truncation, SIB, negative displacement, RIP-relative addresses
and both RSP/RBP default-SS coordinates. Cases include all 16 reserved bits,
all low control/status bits, unaligned and cross-page access, read-only and
absent pages, noncanonical/unmapped operands and complete neighboring payload
preservation. Native FXSAVE before/after independently checks that x87/XMM
payload is unchanged by the transfer.

`check-mxcsr.mjs` then observes the actual C-Wasm MMU and table dispatcher:

| Check | Count |
| --- | ---: |
| Native/cold-C byte-identical emissions | 16 |
| Unchanged pre-lowering native records | 4,096 |
| Direct full CPU/payload comparisons | 4,096 |
| C-dispatch full CPU/payload comparisons | 4,096 |
| Additional RF comparisons | 8,192 |
| Independent native fault comparisons, across dispatch/RF modes | 6,720 |
| CR0/CR4 priority models | 224 |
| Residency wait/retry models | 56 |
| Private-port/state/generation/debug/alignment refusals | 224 |
| Poisoned unrelated-field preservation models | 32 |

CR0/CR4 are not writable by this native user process. Their checks are SDM/
profile models, **not** independent system/physical-hardware fault observations.
AC/TF contexts retain explicit entry refusal; VEX forms and FS/GS memory
addressing remain outside this admitted subset. These tests do not establish
SIMD arithmetic, complete exception/debug closure, Linux boot or package use.

The whole `make -j4 -C src/v2 check` invocation passes without warnings.
Scoped common-compiler ASan/UBSan checks pass. FXSAVE, memory-shift and
SHLD/SHRD C-Wasm regressions pass with their latest native emission records.
Older FXSAVE records predate later common emission changes and are not
interchangeable with the final records. The previously reproduced intermittent
native CALL oracle red is **not** resolved by this passing full run; see the
known-red record.
