## Derive the machine contract, not bytes from a cache miss

E820 describes availability to Linux, not the contents of every physical bus
target. [Linux's boot protocol](https://docs.kernel.org/arch/x86/boot.html)
separates bootloader/firmware bindings from the kernel and memory map.
The [QEMU memory model](https://www.qemu.org/docs/master/devel/memory.html)
also distinguishes RAM, ROM, ROM devices and unassigned regions. It is an
independent architectural reference, never the product execution backend.

For this direct-entry machine, explicitly fix:

```text
0x000000..0x0a0000: initial RAM / loader records
0x0a0000..0x0c0000: unassigned device window; demand remains a supply refusal
0x0c0000..0x100000: reserved erased ROM; every byte is 0xff
0x100000..ram_end: initial RAM / bounded authenticated boot object extents
outside that map: explicit refusal; never infer zero RAM
```

The erased ROM is a product policy, **not** an x86-mandated value, QEMU's
unassigned-memory default, a claim to emulate BIOS/PCI shadowing, or firmware
borrowed from the build host. It contains no SMBIOS/ACPI/MP/option-ROM signatures
or executable BIOS entry. No BIOS/EFI service is exposed. Linux performs its
ordinary scans and decides what absent tables mean. No kernel branch, scan,
instruction or exception is skipped. The entire legacy hole remains E820
reserved, so no allocator is told that the ROM is writable RAM.

Let `M` be physical payload and `p` an admitted ROM byte. The bus transfer is:

```text
read(p) = M[p]
write(p, v): M' = M
RMW(p, f): returns M[p]; attempted write f(M[p]) leaves M' = M
```

These transfers occur only **after** guest canonical-address and PTE RW/U/NX
checks. A rejected guest translation remains a real Linux #PF/#GP/#SS. Physical
ROM itself does not manufacture #PF, suspend for write supply or become RAM.
Read-only page-table storage likewise ignores attempted A/D payload updates;
ordinary RAM page-table updates retain the existing mutation fence.

The same C resident index carries a typed ROM row. Its accepted bus-access mask
is distinct from mutability. A bounded two-fragment reservation records which
physical fragments discard writes; cancellation/trap/stale generation consumes
it without payload publication. For a mixed RAM/ROM write, only RAM fragments
invoke write observers and dirty state, with original byte shifts preserved.
Later-fragment denial preflights before any payload changes. No new JavaScript
bus, scalar interpreter, translation cache, directory, or guest-memory callback
is introduced. The MMU takes mutability from the existing lookup, not a second
lookup or copied page vector.

ROM admission uses only the next virgin payload slot. That slot is beyond every
initial RAM extent; subsequent RAM/ROM appends also consume virgin slots.
Inductively, guest writable aliases cannot address the ROM backing extent.
Initial reopen does not trust arbitrary ROM rows: reconstruct these clean
resources after open. The serialized host owner must still pin directory and
arena; this is not protection against a malicious host owner or SMP proof.

The template needs no stored/fetched firmware payload. Resident projection is
currently one 4 KiB backing page per touched ROM page, bounded to 64 pages for
the whole window. It is reconstructible, never dirty workspace state. This is
not yet shared-template residency or general dirty eviction/recovery.
