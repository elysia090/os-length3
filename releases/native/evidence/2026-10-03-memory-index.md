For operand width `w` in `{16,32,64}` and the original effective address `E`:

```text
s          = sign_extend_w(index)
word_delta = floor(s / w) * (w / 8)
           = (s >> 3) & -(w / 8)
bit        = index & (w - 1)
address    = truncate_address_width(E + word_delta)
```

Because `w` is a power of two, arithmetic shift and the low-byte alignment
mask implement floor division, including negative indexes. No divide,
bit-string allocation, materialized scan or opcode runtime callback is needed.
The index is captured once; address and value arithmetic are emitted SSA.
Only the final adjusted address crosses the existing C-MMU read or
reserve/commit boundary. Testing the original base first would incorrectly
fault when only the adjusted word is mapped. Both modifying arms write and
publish flags/RIP only after commit. BT only reads. CF observes the original
selected bit; ZF is unchanged and undefined OF/SF/AF/PF keep the incoming
representative, rather than being claimed as exact native flag values.

[Intel SDM Volume 2A](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf)
defines signed memory indexes, floor division and positive remainder in
Bit(BitBase,BitOffset), and warns that the full operand word can be accessed
even if the selected bit needs only one byte. The full word, not just that
byte, therefore remains subject to the precise memory boundary.
