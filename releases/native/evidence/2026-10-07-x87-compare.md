## Reverse requirements and the numeric normal form

An extended operand has explicit significand `m`, sign `s`, exponent `e` and
an independently owned physical occupancy tag. f64 cannot distinguish the
one-ulp 80-bit pairs in this gate. We require the exact ordering, signed-zero
equivalence, NaN/unsupported/empty behavior and new exception bits, without
rounding or a materialized floating value.

```text
zero       = (e == 0) && (m == 0)
unsupported= (e != 0) && !(m >> 63)
NaN        = (e == 32767) && (m & 0x7fffffffffffffff)
SNaN       = NaN && !(m & 0x4000000000000000)
invalid    = empty || unsupported_A || unsupported_B
             || (ordered ? any_NaN : any_SNaN)
unordered  = invalid || any_NaN
denormal   = ((e_A == 0 && m_A != 0) || (e_B == 0 && m_B != 0))
             && !unordered
raised     = invalid | (denormal << 1) | (empty << 6)
e*         = e == 0 ? 1 : e
```

Finite magnitudes compare lexicographically as `(e*,m)`. Pseudo-denormals thus
compare at exponent one but still raise DE. Different signs select negative
first; equal negative signs reverse the magnitude order. Both signed zeros
are equal. The only relation outputs needed are CF/PF/ZF: unordered=69,
less=1, equal=64, greater=0. Invalid and unordered cases suppress the lower
priority DE classification.

This expression has ONE common x86 owner. It uses the existing `pl_builder`,
projected compaction, pure-node sharing and dependency-wave scheduling; the
Wasm backend does not re-derive a second float comparison. Source alias
ST(0),ST(0) substitutes the same two input coordinates before compaction.
The measured abstract max is 73 live nodes / span 11, not an x86 instruction
cost, proved global minimum, or a claimed execution-speed improvement.

## State and event publication

The four register FCOMI/FUCOMI/pop variants share a checked descriptor law.
FOP comes from the decoded opcode/ModRM, not the first two source bytes:
otherwise legacy prefixes corrupt the FOP saved on an unmasked exception.

The emitted function performs EM/TS #NM first. A pre-existing unmasked x87
error then produces precise native #MF when CR0.NE is set, or a typed C
`floating_wait` when it is clear. Neither path starts numeric publication.
For a new comparison, the relation/exception DAG is pure. The new bits become
sticky; unmasked errors latch ES/B and the correct FOP, and suppress pop.
FIP is the admitted source coordinate. A completed pop marks only the old
physical TOP slot empty and increments TOP modulo eight; payloads are not
rotated/copied. CW, data registers, XMM/MXCSR and other state remain unchanged.

C owns only the deferred PC FERR wire/PIC/interrupt boundary, not x87
arithmetic or opcode selection. Its FLOATING barrier pins the unretired entry
and is interruptible. The guest handler, not JavaScript, consumes the event.
FNCLEX is a no-wait clear of IE/DE/ZE/OE/UE/PE/SF/ES/B, with #NM before effects.
Completed no-wait clearing deasserts the FERR wire. Port F0h resets the AT
math-error interrupt latch AFTER ordinary C I/O permission admission. PIC
request/service state and the guest CPU/FPU state remain their existing owners.
The raw startup diagnostic now recognizes this C-owned wait distinctly from
memory supply and cannot invent a #MF or source retirement.

Intel describes native versus legacy delivery in
[SDM section 8.7](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf).
The simple [FCOMI instruction table](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf)
is not, by itself, a sufficient oracle for every observed condition-code
detail. The previous fixed incoming flags also failed to distinguish certain
unmasked outcomes; that test weakness is removed below.
